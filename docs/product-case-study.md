# CrossWeb AI · 实际 AI 建站产品的架构案例

[体验真实产品](https://www.crosswebai.com) · [运行精选工程示例](../README.md)

**用户旅程：** 用户通过自然语言创建网站，在同一个已有项目上持续修改页面、结构和功能，并最终得到可预览、可发布的网页。工程目标不仅是生成代码，还包括尽量保留已有内容、应对失败、控制成本和明确任务是否真正完成。

**真实产品主要技术范围：** Node.js 后端、OpenAI Agents SDK、工具调用、Neon PostgreSQL 项目及运行状态、E2B 隔离执行环境、构建与页面预览、结果审核、版本管理、Vercel 发布，以及运行跟踪和用量控制。运行分析包含模型、工具、审核等阶段的耗时与失败分类；Eval 覆盖多种网站类型和多轮修改任务，并使用基于历史失败类型的离线回归测试。

**代表性工程问题：** ① 已有项目的多轮修改不能被新代码无意覆盖；② 模型的工具操作需要运行时权限边界；③ 构建成功不等于满足用户目标；④ 长任务需要处理重复请求、并发、失败恢复及可观察性；⑤ 用可复现案例测试关键边界，但不将离线测试通过率冒充线上成功率。

**公开示例与产品的边界：** [Agent Loop](../src/agent.mjs)、[工具边界](../src/tools.mjs)、[后端请求协调](../src/run-coordinator.mjs) 和 [三个可执行案例](../examples/showcase.mjs) 是**独立编写的脱敏实现**。它们不包括真实生产数据库租约、E2B 与发布代码、商业提示词、客户文件、凭证或真实任务轨迹。

**Trace / Eval 对外演示：** [查看可运行的脱敏实现与受控评测](trace-and-eval.md)。公开的五个场景和离线脚本结果仅反映合成测试，不代表线上模型成功率，也不包含真实客户的 Trace 或专有评审输入。

**技术评审路径：** 先在真实产品体验创建与后续修改，再运行 npm test 和三个离线案例，最后审查代码、边界条件与失败路径。
