# Showcase Architecture / 架构与职责

这是独立重写的有限工程示例，不是私有产品的完整代码。其重点是让模型负责下一步决策，而运行时负责工具权限、任务预算、文件作用域和可验证状态。

请求 → Node.js API → Agent Loop → 模型适配器 → 工具名及参数校验 → 受限文件读写 → 观察结果 → 下一轮决策 / 结果检查。

**运行时约束：** 工具白名单、字段类型验证、真实路径边界、歧义编辑拒绝、最大轮次、最大工具调用量、任务取消和结构化运行摘要。编辑后旧验证结果失效。调用方可使用 requiredChecks 定义必须修改并证明的页面及目标文本；如果一个任务涉及多个 HTML 页面，每一个被修改的页面都需要在最后一次修改之后单独通过检查。CSS、内容保护与视觉质量由外层独立的保留/浏览器验证负责，不能仅凭某个 H1 检查就认定完整任务完成。运行协调器展示单进程请求去重及冲突拒绝，不能视为生产级分布式锁。

**案例范围：** examples/showcase.mjs 涵盖多页面编辑、独立的内容保留检查、工具错误后精准修复和后端幂等。使用脚本化离线模型与合成 HTML/CSS，因而零模型费用、可复现，但不能代替真实浏览器或 UI 质量评估。

**实际产品范围：** E2B 隔离执行、Neon 项目数据/任务状态及版本、预览与发布流程等见 [产品案例](product-case-study.md)，这些商业实现未公开。
## 最新边界细节

- **验证语义：** `runAgent` 只对被编辑 HTML 路由及调用方提供的 `requiredChecks` 负责；本地 HTTP 离线模式返回 `demo_verified`，明确只验证固定脚本。live 模式必须提供目标标题契约，只有检查通过才返回 `contract_verified`，而且不会声称完整自然语言需求或视觉质量已被证明。
- **有界运行协调：** 全部 HTTP 请求（包括没有 `request_id` 的请求）都会占用进程内名额。重复的同 ID 同参数请求仍共享正在运行的 Promise；已完成记录可清理，未完成任务绝不为了释放容量而删除。满额返回 503 及重试提示。完成后 TTL 才开始计时。
- **文件读写：** 工具除了 `realpath` 作用域检查，还使用文件句柄读取与 `fstat` 尺寸复查；POSIX 上用 `O_NOFOLLOW` 防止文件最终组件在检查后被切换为符号链接。这是小型演示的安全收紧，不是对恶意并发修改父目录的 `openat` 级隔离承诺。
- **Trace：** 输入和输出 Token 分别记录完整性；缺任一模型尝试的必要用量时，总 Token 为 `null`，已知的部分和以单独字段呈现。CI 在 Node.js 20/24 上运行覆盖率与所有离线用例。
